# ForenSOC - Implementation Roadmap & Setup Guide

## Quick Start Setup

### Prerequisites
- Python 3.9+
- PostgreSQL 12+ (or SQLite for MVP)
- Docker & Docker Compose (optional)
- Git

### Installation Steps

#### 1. Clone Repository
```bash
git clone https://github.com/yourusername/ForenSOC.git
cd ForenSOC
```

#### 2. Backend Setup
```bash
cd backend
python -m venv venv

# Windows
venv\Scripts\activate

# Linux/macOS
source venv/bin/activate

pip install -r requirements.txt
```

#### 3. Environment Configuration
```bash
cp .env.example .env
# Edit .env with your settings:
# DATABASE_URL=postgresql://user:password@localhost/forensoc
# SECRET_KEY=your-secret-key-here
# DEBUG=false
```

#### 4. Database Setup
```bash
# Create database
createdb forensoc

# Run migrations
alembic upgrade head
```

#### 5. Backend Start
```bash
python -m uvicorn app.main:app --reload --port 8000
```

#### 6. Frontend Setup (React + TypeScript)
```bash
cd frontend-react
npm install
npm run dev
```

#### 7. Access Application
- Frontend: http://localhost:3000
- API Docs: http://localhost:8000/api/docs
- API ReDoc: http://localhost:8000/api/redoc

---

## Docker Setup (Optional)

### Build and Run with Docker Compose
```bash
docker-compose up -d
```

This will start:
- PostgreSQL database on port 5432
- FastAPI backend on port 8000
- React frontend on port 3000

Or build React frontend separately:
```bash
cd frontend-react
docker build -t forensoc-react-frontend:latest .
docker run -p 3000:3000 forensoc-react-frontend:latest
```

## Phase 2: Log Management & Detection (Weeks 4-6)

### Objective
Build a log ingestion and detection subsystem so the platform can consume raw logs, normalize events, and generate meaningful security alerts.

### Architecture Overview
- `LogParser` service processes raw log files and extracts structured data.
- `LogNormalizer` maps parsed events into a common event schema.
- `DetectionEngine` evaluates normalized events against rules and generates alerts.
- `RawEvent` and `NormalizedEvent` tables store ingest history and analysis-ready events.
- `DetectionRule` definitions are stored and managed through the API.
- Alerts generated by the engine link back to source events and detection rules.

### Data Model
- `RawEvent`: id, source, raw_text, ingest_source, status, created_at, metadata
- `NormalizedEvent`: id, raw_event_id, timestamp, source_ip, dest_ip, username, hostname, event_type, severity, outcome, created_at
- `DetectionRule`: id, name, description, severity, mitre_tactic, mitre_technique, pattern, enabled
- `DetectionAlert`: extends `Alert` with source_event_id, rule_id, detector_name

### API Design
- `POST /api/logs/ingest` - upload raw logs or ingest from source
- `GET /api/logs` - list normalized events with filters and pagination
- `GET /api/logs/{log_id}` - get raw/normalized event details
- `GET /api/detection/rules` - list detection rules
- `POST /api/detection/rules` - create/update detection rule
- `GET /api/detection/alerts` - list alerts generated by the engine
- `POST /api/detection/alerts/scan` - trigger manual scan of historical events

### Week 4: Log Parser Service
- Create a reusable parser service for raw log ingestion.
- Implement modular parsers for:
  - Linux `auth.log`
  - Apache/Nginx web server logs
  - Syslog format
  - CSV log imports
- Persist raw text and parser metadata to `raw_events`.
- Add unit tests using sample log files.

### Week 5: Log Normalization & Storage
- Design a normalized event schema for security-relevant fields.
- Build the `NormalizedEvent` ingestion pipeline.
- Implement search/filter API for normalized logs.
- Support filtering by:
  - source IP, destination IP
  - username, hostname
  - event type, severity
  - time range
- Add pagination and sorting to log queries.

### Week 6: Detection Engine
- Build a rule-based detection engine service.
- Implement core rules for initial coverage:
  - SSH brute force detection
  - Repeated failed authentication attempts
  - Suspicious account creation
  - Anomalous login times
- Map detections to MITRE tactic/technique metadata.
- Generate actionable alerts and link them to source events.
- Create a basic Log Explorer UI page in the frontend with:
  - event search
  - aggregation by source/type
  - drill-down to raw event details

**Deliverable**: A working log ingestion and detection pipeline with API and explorer UI
